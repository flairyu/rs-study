# 总纲：Rust 是什么，以及你该怎么学它

> 这份文档是整套教程的地图。**先花 20 分钟读完它**，你对 Rust 的整体印象会建立起来，
> 后面每一章都只是往这张地图上填细节。
>
> 它假设你有 C/C++/Python 基础，所以不会解释「什么是循环」「什么是结构体」。

## 1. 一句话理解 Rust

Rust 想同时拿到三样东西，而过去人们认为这三样最多只能取其二：

| 目标 | C / C++ | Python | Rust |
|---|---|---|---|
| 运行速度 | ✅ 快 | ❌ 慢 | ✅ 快（无 GC、无运行时） |
| 内存安全 | ❌ 靠人 | ✅ 靠 GC | ✅ 靠编译期检查 |
| 并发安全 | ❌ 靠人 | ⚠️ 靠 GIL | ✅ 编译期检查 |

它靠的不是 GC，也不是更聪明的程序员，而是**一套在编译期就能证明"内存不会出错"的类型规则**。
这套规则的核心就是三件套：**所有权（ownership）、借用（borrowing）、生命周期（lifetime）**。
可以毫不夸张地说：**你把这三件事搞懂，Rust 就学会了 70%**。

代价是真实的，别被营销话术骗了：

- **编译期要还债**。C++ 里能跑起来的代码，Rust 可能让你改三遍才能编译。
  但改完之后的代码，通常不会在凌晨三点崩在生产环境。
- **学习曲线陡**。前两周你会同时跟借用检查器、泛型、trait、生命周期打架。
- **有些事确实更啰嗦**。链表、图、双向引用这些"指针密集"的结构，
  在安全 Rust 里要么用索引替代指针，要么上 `unsafe`。

## 2. Rust 的六个核心心智模型

把这六条记住，后面每一章都会反复印证它们。

### 2.1 每个值有且只有一个所有者

```rust
let s = String::from("hello");   // s 拥有这块堆内存
let t = s;                       // 所有权 move 给 t，s 从此失效
// println!("{s}");              // ❌ 编译错误：value borrowed here after move
```

这不是"拷贝"，是**转移**。C++ 里你要写 `std::move` 才发生的事，在 Rust 里是默认行为。

**为什么**：因为没有 GC，编译器必须知道"谁负责释放"。如果两个变量都指向同一块内存，
就得回答"谁负责 free"，答不上来就是 double free。**一人一个**是最简单的答案。

### 2.2 想用别人的值，就借（borrow），别抢

```rust
fn length(s: &String) -> usize { s.len() }   // 借一个不可变引用

let s = String::from("hello");
let n = length(&s);      // 借出去
println!("{s} {n}");     // s 还能用 ✅
```

借用规则（**这一条要背下来**）：

> 在任意时刻，对同一个值，你**要么**拥有任意多个 `&T`，
> **要么**拥有恰好一个 `&mut T`，二者不可兼得。

这条规则一句话就消灭了数据竞争。C 里的「两个线程同时读写一个变量」、
C++ 里的「迭代器失效」，在 Rust 里都是编译错误。

### 2.3 引用的有效期由生命周期标注证明

```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}
```

`'a` 不是"让变量活得更久"的指令，而是**你对编译器的一个承诺**：
「我返回的引用，活得不会比这两个输入更短」。编译器拿这个承诺去检查调用方。

大多数时候编译器能自己推断（叫"生命周期省略规则"），你根本不用写 `'a`。
需要你手写的时候，通常意味着**你的设计里有歧义**，而不是编译器太笨。

### 2.4 用 trait 组合，不用继承

Rust 没有类继承（没有 `extends`）。它用 trait 描述"能做什么"：

```rust
trait Area { fn area(&self) -> f64; }

impl Area for Circle    { fn area(&self) -> f64 { 3.14159 * self.r * self.r } }
impl Area for Rectangle { fn area(&self) -> f64 { self.w * self.h } }
```

对照你的已有知识：

| | C++ | Python | Rust |
|---|---|---|---|
| 复用行为 | 继承 + 虚函数 | 继承 + 鸭子类型 | trait + 泛型（静态）或 `dyn`（动态） |
| 运行时代价 | 虚表 | 字典查找 | 泛型=0 开销；`dyn`=一次虚表跳转 |
| 多重"继承" | 菱形问题 | MRO | 想 impl 多少 trait 就 impl 多少 |

### 2.5 错误是值，不是异常，也不是错误码

```rust
fn parse_age(s: &str) -> Result<u8, String> {
    let n: u8 = s.trim().parse().map_err(|_| "不是数字".to_string())?;  // ← ? 提前返回
    if n > 150 { return Err("年龄超出范围".into()); }
    Ok(n)
}
```

- **没有异常**：不会有意外的控制流跳转（Python 的 `except` 能接住任何东西，这在 Rust 里不存在）。
- **不是错误码**：编译器强制你处理 `Result`（`#[must_use]`），忘了处理会有警告。
- 调用方要么 `?` 往上传播，要么显式 `match` / `unwrap`。**错误路径无法被忽略**。

### 2.6 零成本抽象：高级写法不等于慢

```rust
let sum: i64 = nums.iter().filter(|&&x| x % 2 == 0).map(|&x| x as i64 * x as i64).sum();
```

这行和手写的 `for` 循环编译出的机器码**基本一样**。原理是泛型**单态化**：
编译器为每个具体类型生成一份专用代码，内联之后迭代器链就消失了。

对比：Python 的迭代器链慢，是因为每一层都是一个 Python 函数调用。
Rust 的抽象是**编译期**的。

## 4. 与 C/C++/Python 的差异地图（速查）

| 话题 | C | C++ | Python | Rust |
|---|---|---|---|---|
| 变量默认 | 可改 | 可改 | 可改 | **不可改**（`mut`） |
| 类型转换 | 隐式 | 隐式+显式 | 隐式 | **必须 `as`/`From`** |
| 字符串 | `char*` | `std::string` | `str` | `String`（拥有）/ `&str`（借用） |
| 空值 | `NULL` | `nullptr` | `None` | **没有 null**，用 `Option<T>` |
| 错误 | 返回码/errno | 异常/返回码 | 异常 | `Result<T,E>` + `?` |
| 释放内存 | `free` | RAII / `delete` | GC | 作用域结束自动 `Drop` |
| 多态 | 函数指针 | 虚函数 | 鸭子类型 | trait（静态/动态） |
| 数组越界 | UB | UB | 抛异常 | **panic**（不是 UB） |
| 接口文件 | `.h` | `.hpp` | 无 | 无（`mod` + 可见性） |
| 构建 | make | cmake | pip/setuptools | **cargo**（一体化） |
| 包管理 | 无 | vcpkg/conan | pip | **cargo + crates.io** |
| 测试 | 第三方 | 第三方 | pytest | **内建 `#[test]`** |
| 并发安全 | 靠人 | 靠人 | GIL | **编译期检查**（`Send`/`Sync`） |

### 从 C/C++ 过来最容易踩的五个坑

1. **不要试图"骗过"借用检查器**。`unsafe` 不是逃生舱，它是「我自己负责」的签字。
   第 15 章之前不要碰它。
2. **`let s = other;` 是移动，不是拷贝**。C++ 的直觉会害你。想拷贝就 `.clone()`（有代价）。
3. **`&T` 和 `T` 是两种东西**。函数签名里写 `&str` / `&[T]` 是默认选择，不是偷懒。
4. **整数不会隐式提升**。`let x: i64 = some_i32;` 编译不过，得写 `as i64`。
5. **`println!("{}", x)` 里 `x` 默认是借用**，不会拿走所有权（宏会帮你加 `&`）。

### 从 Python 过来最容易踩的四个坑

1. **没有 GC，也没有"随便共享"**。`a = b` 对 `list` 是复制引用，对 Rust 的 `Vec` 是移动。
2. **没有异常**。`?` 和 `match` 取代了 `try/except`，而且**不能忽略**。
3. **闭包捕获有所有权语义**。Python 里闭包随便抓变量，Rust 里要区分 `Fn`/`FnMut`/`FnOnce`。
4. **可变性会传染**。`&mut` 同一时刻只能有一个，这经常迫使你重构数据结构（这是好事）。

## 5. 怎么用这套教程（重要）

### 5.1 单章循环

```bash
cd /home/yxb/code/rs-study

# ① 读文档
less docs/01-syntax/ch03-ownership.md

# ② 跑一次测试，看它怎么失败（这一步别跳过，它是你的"题目"）
python3 tools/check.py ch03_ownership

# ③ 打开练习，把 unimplemented!() 换成你的实现
$EDITOR exercises/ch03_ownership/src/lib.rs

# ④ 再跑
python3 tools/check.py ch03_ownership

# ⑤ 过不了？让 AI 按提示层级指导你（不是直接给答案）
python3 tools/ai_review.py ch03_ownership --hint 1   # 只给方向
python3 tools/ai_review.py ch03_ownership --hint 2   # 给关键 API
python3 tools/ai_review.py ch03_ownership --hint 3   # 几乎给答案

# ⑥ 真的想不开再看参考答案（文档最后 <details>）或直接要完整实现
python3 tools/ai_review.py ch03_ownership --solution

# ⑦ 全绿 → 下一章
python3 tools/check.py --next
```

### 5.2 铁律

1. **每题至少自己挣扎 10 分钟**再看提示。挣扎本身就是学习。
2. **不要改 `tests/chapter.rs`**。它是裁判，不是障碍。
3. **编译器报错是第一手教材**。`cargo build` 的错误信息里通常直接写了修法，
   尤其是 "help:" 那一段。学会读它，比学会写更重要。
4. **每章学完做一次"空白纸复述"**：合上文档，写下本章三个核心结论。
   写不出来说明没学会，回去重读。
5. **允许自己改设计**。如果借用检查器一直拦你，八成是数据结构选错了，
   而不是编译器在刁难你——这是 Rust 最有价值的一种"被迫成长"。
6. **不要提前看答案**。参考答案在每章文档最后的 `<details>` 折叠块里，
   另外 `solutions/` 目录下有一份**被测试验证过**的完整实现：
   ```bash
   python3 tools/check.py --solutions     # 应显示 16/16 全绿、48/48 通过
   ```
   后者存在的意义是「保证题目本身没写错」，不是给你抄的。
   如果不看答案就写不出来，说明该回去重读文档对应小节，而不是去 `solutions/` 里找。

### 5.3 你可以信任这套题目

`tests/chapter.rs` 是裁判，而**裁判本身也被验证过**：`solutions/` 里的参考实现
通过 `#[path]` 复用同一份测试文件，所以「参考答案全绿」等价于
「这 48 道题都可解、期望值都自洽」。构建过程中正是靠这个自检抓出了 5 处真实的题目 bug
（比如某题测试期望 335，但正确值是 305；某题的 `rest()` 期望与同一测试里 `pos == 7` 的断言互斥）。

所以当你写不出来时，**先默认是自己错了**，但如果你确信规格与测试矛盾，
去 `exercises/<crate>/tests/chapter.rs` 里核对断言消息——每条断言都带中文说明，
它写的就是期望的语义。

### 5.4 卡住时的决策树

```
编译不过？
├── 报错里有 "help:" → 照它说的改
├── 报错是 borrow/move/lifetime → 回第 3、4、10 章重读对应小节
└── 报错是 trait bound 不满足 → 回第 9 章，看它要求哪个 trait

编译过了但测试失败？
├── 边界情况（0 / 空 / 负数 / 越界）没处理 → 先把测试里的用例逐个手算一遍
└── 逻辑对了但格式不符 → 看文档里的精确输出要求

完全没思路？
└── python3 tools/ai_review.py <crate> --hint 1，然后只读提示的前半句
```

## 6. Rust 不适合什么（避免用错工具）

- **快速原型 / 数据科学探索**：Python 仍然更快。Rust 的编译期检查在"还没想清楚需求"时是负担。
- **GUI 桌面应用**：生态有（`egui`/`tauri`/`iced`），但成熟度不如 Qt/Electron。
- **大量相互引用的数据结构**（图、双向链表、GUI 控件树）：
  安全 Rust 里很别扭，通常改用「索引 + `Vec`」或 arena。这正是很多人最终写 `unsafe` 的地方。
- **学习第一门语言**：不适合。你已经会 C/C++/Python，所以正好。
