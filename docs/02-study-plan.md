# 学习计划：4 周速通 / 8 周扎实

> 你有 C/C++/Python 基础，所以目标不是"学会编程"，而是**换一套内存与类型的心智模型**。
> 时间预算按「每天 1.5–2 小时，每周 5 天」估算。

---

## 1. 两种节奏，选一个

| | 4 周速通 | 8 周扎实 |
|---|---|---|
| 每天 | 2–2.5 小时 | 1–1.5 小时 |
| 覆盖 | 第 1–16 章 + 挑 2 个框架章 | 第 1–21 章全做 |
| 适合 | 赶项目、想快速上手能写 | 想真正掌握、以后拿它当主力语言 |
| 代价 | 第 9–13 章只能混个脸熟 | 需要更强的自律 |
| 每周负荷 | 4 章 | 2–3 章 |

**建议**：先按 4 周速通走完第 1–8 章，此时你已经能读懂大部分 Rust 代码。
第 9 章之后自己决定要不要放慢——很多人在这时会主动放慢，因为开始有意思了。

## 3. 8 周扎实版

把上面的 4 周内容摊开，每周加两件事：

1. **每周一次「从零重写」**：挑上周的一个练习，不看任何资料重新实现一遍。
2. **每周一次 `cargo clippy -- -D warnings` 清零**：强迫自己写出地道代码。

额外插入的深挖内容：

| 周 | 深挖主题 | 自己找答案的问题 |
|---|---|---|
| 2 | 单态化与代码膨胀 | 泛型函数给 3 种类型用，二进制里会有几份代码？ |
| 3 | `Rc<RefCell<T>>` 何时是坏设计 | 为什么官方说"能不用就不用"？ |
| 4 | `Send`/`Sync` 与 `!Send` | 为什么 `Rc` 不能跨线程？编译器怎么知道的？ |
| 5 | 生命周期省略规则 | 为什么 `fn f(&self) -> &str` 不用写 `'a`？ |
| 6 | `impl Trait` vs `dyn Trait` | 各自让二进制变大还是变小？ |
| 7 | 错误处理分层 | 库用 `thiserror`、应用用 `anyhow`，为什么？ |
| 8 | `unsafe` 的边界 | 写一个 `unsafe fn`，并用 Miri 检查它 |

## 4. 每日 90 分钟模板

```
00–25 min  读文档，边读边在脑子里预测"这段能不能编译"
25–30 min  跑 python3 tools/check.py <crate>，看题目要求
30–70 min  写实现，卡住先自己 debug 5 分钟，再上 --hint 1
70–80 min  全绿之后，读一遍参考答案，对比你的写法和它的写法
80–90 min  写 3 行笔记：今天学到的 + 今天踩的坑 + 还没懂的
```

**笔记格式**（建议存成 `notes/YYYY-MM-DD.md`）：

```markdown
## 2026-10-12 · 第 3 章 所有权
学到：String 赋值是 move，i32 是 Copy；`&s` 不转移所有权
坑：`for w in words` 会消费 Vec，之后不能再 `words.len()`
没懂：为什么 `fn f(s: String) -> String` 里返回 s 不算二次 move？（其实算，但返回是合法的）
```

最后一项"没懂"最值钱。攒够 5 条就去问 AI 或者翻文档。

## 5. 里程碑项目（学完该做什么）

不要只做题，**每阶段要有一个能跑起来的东西**。这三个是我建议的最小项目：

### 里程碑 1（学完第 8 章）：命令行词频统计

```bash
cargo new --bin wordfreq
```

要求：
- 读一个文本文件（`std::fs::read_to_string`）
- 统计词频（`HashMap`）
- 按次数倒序输出前 10（迭代器 + `sort_by`）
- 用 `?` 而不是 `unwrap` 处理 IO 错误
- 支持 `--top N` 参数（手写 `std::env::args` 解析即可）

**验收**：能对自己写不出代码的地方说出"缺哪个 std API"。

### 里程碑 2（学完第 13 章）：并发下载器骨架

```bash
cargo new --bin fetchsim
```

写一个**模拟**下载器（不真的联网）：
- N 个"任务"，每个任务 sleep 随机毫秒
- 用 `thread::spawn` + `mpsc` 汇报进度
- 主线程实时打印 `[3/8] 完成: task_3`
- 加一个 `Arc<Mutex<Vec<String>>>` 记录完成顺序，最后打印

**验收**：能解释为什么这里不能只用 `Vec` 而必须 `Arc<Mutex<_>>`。

### 里程碑 3（学完第 20 章）：带 SQLite 的 REST API

把 axum 和 sqlx 合起来：一个只有 `GET /todos` 和 `POST /todos` 的服务，
数据落 SQLite。这是**最能拿出去给别人看**的第一个 Rust 项目。

## 6. 进度自检表

每完成一批章节，回答这些问题。答不上来就回去补。

**第 1–4 章之后**
- [ ] 为什么 `let s2 = s1;` 之后 `s1` 不能用了？`i32` 为什么不这样？
- [ ] 什么时候只能有一个 `&mut T`？为什么这条规则能防住数据竞争？
- [ ] `&str` 和 `String` 差在哪？什么时候用哪个？

**第 5–8 章之后**
- [ ] `Option<T>` 比 `null` 好在哪？给出一个具体场景。
- [ ] `?` 运算符展开成什么？为什么它只能用在返回 Result/Option 的函数里？
- [ ] 用迭代器链替换一个 `for` 循环 + `if` + `push`。

**第 9–13 章之后**
- [ ] `impl Trait` 和 `dyn Trait` 的取舍是什么？
- [ ] 为什么 `Rc` 不能跨线程，而 `Arc` 可以？编译器靠什么判断？
- [ ] `async fn` 被调用时会执行吗？什么时候才真正跑？
- [ ] 为什么并发写 `Vec` 编译不过，而 `Arc<Mutex<Vec>>` 可以？

**第 14–16 章之后**
- [ ] package 和 crate 的区别？
- [ ] `unsafe` 打开了哪五种能力？它**没有**关掉什么？
- [ ] std 里为什么没有 async 运行时、正则、随机数？

**学完框架章之后**
- [ ] 我能从零建一个 axum 服务并加上一个自己的路由。
- [ ] 我知道 sqlx 的 `query_as!` 在编译期检查什么。

## 7. 常见"卡住"和对应动作

| 症状 | 真实原因 | 动作 |
|---|---|---|
| 天天跟借用检查器打架 | 你在用 C 的思路设计数据结构 | 回第 4 章；试着把"指针图"改成"索引 + Vec" |
| 满屏 `unwrap()` | 没理解 `?` 和错误类型 | 回第 6 章；给函数换 `Result` 返回 |
| 泛型签名写到一半写不下去 | trait bound 没想清楚 | 回第 9 章；先写具体类型，跑通后再泛化 |
| 生命周期标注越加越多 | 通常是想返回借用而不是拥有 | 回第 10 章；考虑返回 `String`/`Vec` 而非引用 |
| `async` 代码不执行 | 忘了 `.await` 或没起运行时 | 回第 13 章 |
| 编译太慢想放弃 | 每次都 `cargo build` | 改用 `cargo check` |
